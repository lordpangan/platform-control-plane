# ADR 0010 — Own the Backstage templates; turn off generated forms

- **Status:** Accepted
- **Date:** 2026-10-11
- **Changes:** part of [ADR 0009](./0009-backstage-deployment.md)'s consequences
  (the generated templates and the upstream edit template)

## Context

[ADR 0009](./0009-backstage-deployment.md) shipped Backstage with templates we
didn't write:

- **Create forms generated by the ingestor**, one per XRD. They defaulted to a
  folder ArgoCD doesn't watch, added no sync-wave, built a wrong
  `source-file-url` (`temp/...`) with the `custom` layout, and didn't enforce
  `required`. The layout default is hard-coded. In plugin version 2.7.1 no
  config or XRD annotation changes it.
- **The edit template, loaded at runtime from an upstream repo**
  (`vrabbi-backstage/gitops-updater-template`). It deep-merges the form into the
  file, so removals do nothing. It writes `""` for a cleared field, which then
  fails the XRD. Its branch name is fixed per file, so an open PR blocks every
  new edit. And someone else's repo decided what our portal does with our PAT.

## Decision

**We write the templates, keep them in platform-gitops next to the API they
serve, and turn off form generation.**

- **Create:** `definitions/<api>/backstage-template.yaml`, a hand-written
  `kind: Template`. It builds the claim (`serialize:yaml` → `fs:write`) with
  `infra-requests/<name>.yaml`, the sync-wave, owner and `source-file-url`, and
  opens a PR. The form enforces `required`, `enum` and `pattern`.
- **Edit schema:** a second document in the same file, a hand-written
  `kind: API` named `<kind>-<group>--<version>`. The updater field reads its
  fields from there. Generation used to make it; with generation off, nothing
  else does.
- **Edit:** `definitions/_shared/backstage-template.yaml` (`update-claim`), one
  template for every kind. A copy of upstream with three changes: replace
  `spec` instead of merging, drop `""` and empty objects, and a unique branch
  per run.
- **Generation off:** `xrds.enabled: false`. `ingestAllXRDs` stays on, because
  it also tells the ingestor which XR kinds to catalog.
- **Wiring:** one catalog `url` location with a glob,
  `definitions/*/backstage-template.yaml`, `allow: [Template, API]`. The ArgoCD
  app for `definitions/` excludes `*/backstage-template.yaml`. The upstream
  location is removed.

## Alternatives considered

- **Keep generation, and fix each PR by hand.** Pick `custom` + `infra-requests`,
  then fix the URL and add the wave in every PR. Rejected: it's a manual step
  on every request, and the edit-flow bugs remain.
- **Keep generation, but hide the generated forms** with the
  `exclude-from-catalog` XRD annotation. Rejected: the same filtered XRD list
  also decides which XR kinds are ingested, so the XRs leave the catalog too.
- **Change the repo layout to match the generator** (`<cluster>/<ns>/<Kind>/`).
  Rejected for now: still no sync-wave, still no `required`, and it gives up
  `infra-requests/` (ADR 0001) for a plugin's convention.
- **Generate our templates from the XRDs with a script.** That would remove the
  copied schema. Not now: a script plus a CI check to own. Revisit if the
  schema copies start to drift.
- **Upgrade the plugins in our own image.** Upstream 4.x adds a
  `terasky.backstage.io/target-path` XRD annotation that fixes the path and the
  URL. Deferred: it needs our own image, a separate track on the ROADMAP. It
  wouldn't fix the edit flow, so `update-claim` stays either way.

## Consequences

- Requests land in the right folder with the wave and a working
  `source-file-url`. Edits can remove fields, and don't block each other.
- Every template we serve comes from our own repo, reviewed by PR. No upstream
  repo controls what our PAT does.
- **The API schema is copied by hand** into each `kind: API` document. A field
  added to the XRD but not to the copy is missing from the edit form, and
  `update-claim` would then **drop** it on the next edit, since it replaces the
  whole `spec`. Each `backstage-template.yaml` carries a comment to change both
  together.
- **A new XRD no longer gets a form for free.** Each one needs its own
  `backstage-template.yaml`. `XEKSCluster` doesn't have one yet: it's held back
  until the own-image decision, which may bring corrected generated forms back.
- YAML comments in claim files are lost on edit (the file is parsed and
  written back).
