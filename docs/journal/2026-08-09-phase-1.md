# 2026-08-09 — Phase 1: building the brain

**Goal:** automation that stands up the management cluster (kind) with Crossplane,
Kyverno, and ArgoCD — runnable locally *and* on the Proxmox VM from one codebase.

## What I built

- **Ansible as the single source of truth** (`ansible/`): one playbook (`site.yml`),
  two inventories (`local` = `connection: local`, `proxmox` = SSH), versions
  pinned in `group_vars/all.yml`.
- **Roles:** `bootstrap` (installs docker/kind/kubectl/helm on a Debian/Ubuntu VM,
  VM-only), `preflight` (fail fast if a tool is missing), `kind_cluster` (create
  if absent), and `crossplane` / `kyverno` / `argocd` (Helm, pinned charts).
- **`Makefile`** wraps it: `make up`, `make up-vm`, `make down`, `make status`,
  `make argocd-password`.
- **`devbox.json`** pins the toolchain; README also lists a Homebrew fallback.
- **kind config** with ingress-ready + 80/443 port mappings for later.
- **ADR 0003** records: kind, Ansible-as-SoT, Helm.

## Decisions

- **Shell out to `helm`/`kind`/`kubectl`** instead of the `kubernetes.core` Ansible
  modules — keeps the dependency surface to just the CLIs devbox provides (no
  Python `kubernetes` lib).
- **Helm for all three components** (idempotent `upgrade --install`, pinned).

## Status / honesty

- YAML validated (parses clean). **Not yet run** — no cluster was spun up (Docker
  daemon was off and the tools aren't installed on this machine; build-only by
  choice). So Ansible module usage, Jinja, and idempotency are **unverified**
  until someone runs `make up`.

## Version check (2026-08-09)

Verified every pin in `group_vars/all.yml` against upstream (Helm repo indexes,
kind releases, dl.k8s.io) and moved them to the latest **stable** (skipping the
RC builds Artifact Hub surfaced for Crossplane/Kyverno). All my first-pass
guesses were stale:

- Crossplane chart 1.18.0 → **2.3.4** (Crossplane **v2** — matches backstack's v2 XRD API)
- Kyverno chart 3.3.4 → **3.8.2** (app v1.18.2)
- argo-cd chart 7.7.7 → **10.3.0** (app v3.5.0)
- kind v0.24.0 → **v0.32.0**; node image now **digest-pinned** `kindest/node:v1.36.1@sha256:3489…ebd5`
- kubectl v1.31.2 → **v1.36.1** (matches the node image)

Two caveats to watch on the first real run:
- **Crossplane v2** is a big jump from v1 (namespaced XRs, no separate claim kind
  by default). Good for us (backstack uses v2) but v1-era tutorials won't match.
- **Kubernetes 1.36 is brand new.** Charts are latest-stable so should support it;
  if a component misbehaves, fall back to an older kind node image (kind v0.32.0
  also ships `v1.35.5@sha256:ce977…ac95`).

## First real run — on the Proxmox VM (2026-08-09)

Ran `make up-vm` end-to-end. **Result: green.** `platform-brain` kind cluster
(k8s v1.34.0) with Crossplane 2/2, Kyverno 4/4, ArgoCD 8/8 — 0 not-Running.

**Adaptations for this VM** (it already ran backstack):
- `lpangan` has no passwordless sudo → **skipped the `bootstrap` role**, used the
  VM's existing **devbox-global** tools via a `tools_path` PATH append.
- devbox kind is v0.30.0 → set `kind_node_image: ""` so kind picks its own
  compatible image (got v1.34.0) instead of the v1.36.1 pinned for a fresh v0.32 VM.

**Bugs I hit and fixed (the "learn by doing" part):**
1. `stdout_callback = yaml` — that callback was removed in ansible-core 2.21.
   Switched to `result_format = yaml`.
2. `kind --config` pointed at a path on my Mac, but kind runs on the VM → added a
   task to **stage the config onto the target** first.
3. **Variable precedence:** I set `tools_path`/`kind_node_image` in the inventory's
   *group* `vars:`, but playbook `group_vars/all.yml` outranks that and clobbered
   them (tools vanished from PATH; node image reverted to the incompatible v1.36.1).
   Fix: set them as **inventory host-vars** (which outrank playbook group_vars).
4. `ansible_facts.env` isn't populated during the initial Gathering Facts task →
   kept `ansible_env.PATH` (tolerant of being unset) and silenced the deprecation.

**Added:** `make down-vm` + `destroy.yml` (the Makefile only had a *local* `down`).

## Day-2 tests (all green, no hiccups)

1. **Re-apply / modify:** re-ran `make up-vm` on the live cluster → in-place
   `helm upgrade` (all releases rev 1→2), pods stayed healthy, `failed=0`. This is
   the modify mechanism — change a version/value in group_vars, re-run, same path.
2. **Delete:** `make down-vm` → `No kind clusters found`, no leftover containers.
3. **Recreate:** `make up-vm` on the empty VM → fresh cluster, releases back at
   rev 1, all pods healthy.
