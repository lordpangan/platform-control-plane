# 2026-08-09 — Phase 0: setting the table

**Where I am:** starting the platform engineering portfolio. Goal: build a small
internal developer platform, following the backstack pattern, as a learning
playground and portfolio piece. Journaling as I go.

## What I did today

- Wrote the [roadmap](../../../ROADMAP.md): 10 phases (0–9), from setting up the
  management cluster to a full golden path with observability, guardrails, a
  Backstage portal, and day-2 proof.
- Settled the repo/cluster shape (see [ADR 0001](../adr/0001-two-repos-two-clusters.md)):
  two repos (`platform-control-plane`, `platform-gitops`), two clusters
  (management on a Proxmox VM, workload on EKS).
- Settled the abstraction stance (see [ADR 0002](../adr/0002-backstage-front-door-repo-escape-hatch.md)):
  Backstage is the front door, the Git repo is the escape hatch.
- Scaffolded both repos: READMEs, `docs/adr/`, `docs/journal/`.

## Decisions I wrestled with

- **`platform-iac` was a bad name** for the repo holding app claims — a claim is
  a developer app request, not infrastructure code. Renamed to `platform-gitops`
  with folders split by template-vs-request (`definitions/`, `infra-requests/`,
  `app-requests/`).
- **Real AWS EKS from the start**, not a local simulation — accepting the cost in
  exchange for real cloud IAM/VPC/EKS experience. Teardown discipline matters.

## What's next (Phase 1)

Build the brain: an Ansible playbook that spins up a kind cluster on the Proxmox
VM with Crossplane + Kyverno + ArgoCD, plus a local one-command path so a reader
can try it on their own laptop.
