# 2026-08-11 — Phase 2, Step 3: raw Workspace smoke test (+ engine switch to OpenTofu)

**Goal:** before wrapping anything in XRDs, prove the whole chain by hand — a
single `Workspace` that runs IaC against AWS and cleanly tears down.

## The engine switch: Terraform → OpenTofu

Mid-test, the raw `Workspace` failed and the debugging surfaced that
`provider-terraform` bundles **Terraform 1.5.5**. That's not a bug — it's a
license line: HashiCorp moved Terraform to the **BSL at 1.6**, and the
Apache-2.0 `provider-terraform` deliberately froze at the last open-source
Terraform and will never move past it.

So we switched engines to **`provider-opentofu` (v1.1.5)**, which runs
**OpenTofu 1.10** — the Linux Foundation's Apache-2.0 fork. Same design
(`Workspace`, `ClusterProviderConfig`, inline HCL, `terraform-aws-modules`); the
only real differences are the API group (`opentofu.m.upbound.io`) and the
package. The `providers/` role was already parameterized, so the swap was a
one-file-ish change — and the var names are now engine-agnostic
(`engine_provider_*`, `engine_api_group`) so a future swap is trivial.

Bonus: OpenTofu 1.10 retroactively confirms our **DynamoDB locking** choice was
fine (S3 native locking needs a newer engine, but DynamoDB works everywhere) and
unlocks modern features (plural backend args, state encryption, etc.).

## The smoke test

A hand-written namespaced `Workspace` (inline HCL) that creates one **bare
`aws_vpc`** — chosen because it's **free** (a VPC with no NAT/EIP costs nothing),
it's **in-scope** for the scoped IAM policy (`ec2:*`), and it rehearses the real
network layer. (First draft used an SSM parameter, but the scoped policy has no
`ssm` — good catch, switched to the VPC.) The module declares its own S3 backend
with a per-test key; `provider "aws"` comes from the `ClusterProviderConfig`.

## Bugs hit and fixed (learn by doing)

1. **The backend authenticates separately from the provider.** First failure:
   *"no valid credential sources for S3 Backend found."* The `provider "aws"`
   block's creds don't reach the S3 backend (backend init happens first). Fix:
   point the backend at the same creds file the `ClusterProviderConfig` writes —
   `shared_credentials_files = ["aws-creds.ini"]` (static path; backends can't
   interpolate, so no `${path.module}`).
2. **Argument name is engine-version-specific.** On Terraform 1.5.5 the arg is
   the **singular** `shared_credentials_file` (the plural was added in TF 1.6);
   on OpenTofu 1.10 it's the **plural** `shared_credentials_files`. This mismatch
   is what exposed the 1.5.5 freeze in the first place → the switch.
3. **State lives under an `env:/<name>/` prefix.** provider-opentofu runs a named
   OpenTofu workspace per Crossplane `Workspace`, so state landed at
   `env:/sandbox-smoke/smoke/terraform.tfstate` — automatic per-resource state
   isolation on top of our per-layer `key`.

## Result (verified end to end)

- **Create:** `Ready=True`; real VPC `vpc-…c55` (`10.42.0.0/16`, available);
  output `vpc_id` surfaced; state object in S3; lock digest in DynamoDB.
- **Teardown:** delete the `Workspace` → `tofu destroy` → VPC gone, state cleared,
  no orphans.
